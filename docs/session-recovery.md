# 会话恢复

入口仅有 `jarvis --resume`（TUI 历史选择器）和 `jarvis --resume sess-xxx`
（指定会话）。普通 `jarvis` 仍创建新会话，`--replay` 仍用于观察历史事件。

## 保存与恢复

- `meta.json` 保存会话 ID、项目目录、标题、更新时间、run 列表和最近运行状态。
  写入时先写同目录临时文件，再原子替换。旧版元信息缺少新增字段时使用兼容默认值。
- `thread.jsonl` 是对话恢复的数据源。用户输入先保存；模型的完整响应在执行工具
  之前保存；每个工具结果返回后立即单独追加。加载时合并同批工具结果，保持模型协议合法。
  流式生成中尚未组成完整模型响应的文本不作为可恢复消息。
- `notes.md` 在下一轮运行时重新读取。Global/Project Context 也按当前文件加载。
- 自动或手动压缩会先备份原对话，再原子替换有效历史。后续消息接在摘要之后保存。
- `events.jsonl` / Trace 保持原有观测用途。恢复界面直接渲染对话快照，避免回放旧事件时
  误挂载审批或重复执行运行逻辑。

Core 收到 `session.list` 时只扫描元信息并过滤当前项目的聊天会话；收到
`session.resume` 时才加载并校验历史。成功后进入 `waiting_for_input`，不会创建 Runner。
第一次新输入才开始新的 run，并使用原会话历史。已关闭的聊天会话可以重新打开。
执行中的会话通过当前 Core 的锁判定 busy，恢复请求会拒绝。

## 中断边界

本方案恢复的是会话上下文，不保存 Python 协程、后台进程、旧审批或工具内部执行位置。
磁盘元信息仍标记 running 而当前 Core 没有执行锁时，视为上次执行中断。
对缺失结果的工具调用补入同 ID 的错误结果，明确说明实际效果未知；再追加一次中断提示。
重复恢复不重复补入这些记录。下一次输入之前不会自动调用模型或工具。

工具可能已经产生副作用，但尚未写入结果，因此不承诺工具恰好执行一次；继续任务前
需要重新检查实际文件或外部状态。若会话在磁盘写入失败时无法保存模型响应，停止运行，
不会继续执行该响应要求的工具。文件逐条 flush 并关闭，未承诺断电级别的持久化。

恢复不会回滚文件或切换 Git 分支。最后一条尚未写完的 JSON 可在备份后截去，
完整坏行和历史中间的调用配对错误会阻止恢复，保留文件供人工检查。

## 手动验证

1. 更新代码后，在待测试的项目目录执行 `jarvis core stop`。
2. 执行 `jarvis`，发送几轮消息，让 Agent 读取文件、写入一条 Note；记下界面会话 ID。
3. 退出 TUI，执行 `jarvis --resume`。验证列表标题、键盘选择、历史消息和工具结果显示。
4. 发送“继续，复述刚才的目标和笔记”，确认原上下文和 Notes 生效。
5. 再次退出并执行 `jarvis core stop`，用 `jarvis --resume sess-xxx` 打开同一会话，
   验证 Core 重启后仍能恢复，且打开后不会自动开始执行。
6. 让 Agent 停在工具审批或耗时工具处，关闭 Core，再恢复；确认出现中断提示，
   不重新弹出旧审批，也不自动重跑工具。检查工作区后再决定如何继续。
7. 对有足够历史的会话执行 `/compact`，完成后退出再恢复，确认摘要与后续消息保留。
8. 使用不存在的 ID，确认显示错误且不悄悄新建会话；在空项目执行 `jarvis --resume`，
   确认空列表可以 Esc 退出或明确新建。

自动测试覆盖重建 SessionManager、实际 IPC + 无头 TUI、逐条持久化时序、写入失败、
中断补齐幂等、损坏历史处理、压缩后恢复以及两个 CLI 入口；模型使用离线替身。
